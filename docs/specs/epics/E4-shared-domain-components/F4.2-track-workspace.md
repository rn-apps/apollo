The one listing of media items: ngkit's grid, a selection toolbar, and the media
editor. Every screen that lists tracks or staged files uses it, configured by
inputs.

## Design

Inputs:

- `source`: a `MediaListSource` with `fetch(pageToken, pageSize, query, sort)`
  returning `{items, nextPageToken, totalSize}`, and a target kind;
- `columns`: a named column set (`library`, `album`, `playlist`, `errors` or
  `inbox`) from `domain/workspace/columns.ts`. Each column maps a field to a
  cell template;
- `rowActions` and `bulkActions`: action descriptors, each with a capability
  key, shown in the selection toolbar or row menu;
- `baseQuery`: a query the screen fixes (an album, a facet value), combined with
  the URL's `q`.

The URL owns `q`, `sort` and `item` (F2.5). Column visibility and order persist
per column set in `setting` through the API.

Selection drives the toolbar: a SelectionChip, the bulk actions, "Edit N"
(opening the bulk edit panel, F4.7), and the screen's own bulk actions (add to
playlist, promote, recheck). Activating a row opens the media editor on its
target.

A screen supplies a source, a column set and actions. It never renders its own
table of tracks.

## S4.2.1 — Workspace over a source and column set

**State:** New

**Acceptance:**

- `S4.2.1: columns from set`: the `library` and `inbox` sets render their own
  columns over the same component.
- `S4.2.1: url owns sort`: a sort header click updates `sort` in the URL, and
  loading the URL restores the sort.
- `S4.2.1: base query`: a `baseQuery` of `album_id:7` is ANDed with the URL `q`
  in the source call.

## S4.2.2 — Selection toolbar and actions

**State:** New

**Acceptance:**

- `S4.2.2: bulk actions`: selecting 3 rows shows "3 selected", "Edit 3" and the
  screen's actions. Clearing the selection hides them.
- `S4.2.2: capability`: an action whose capability is unavailable is disabled,
  with its reason.
- `S4.2.2: row opens editor`: Enter on a focused row opens the media editor on
  that row's target.
