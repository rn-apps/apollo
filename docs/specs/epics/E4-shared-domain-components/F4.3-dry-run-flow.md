Preview, diff, confirm, apply, and offer undo. This is the only way the UI
performs a mutation ([ADR-0009](../../../adr/ADR-0009.md)).

## Design

`DryRunFlow.run({ title, preview, apply, render? })`:

1. Calls `preview()`, which returns a `Plan` of
   `{items: [{target, before, after}], refusals: [{target, code, message}], token}`.
1. Opens a confirm with a diff table of the changed fields per item, a refusal
   list grouped by problem code, and the counts. With an empty diff it reports
   "Nothing to change" and does not offer Apply.
1. On confirm, calls `apply(plan.token)`. That returns a result with a
   `batch_id`, or a `JobRef`.
1. Shows a toast with the result and an **Undo** action that calls
   `POST /v1/audit/batches/{batch_id}/undo` through the dry-run flow itself.
   For a `JobRef`, it shows job progress instead.

A stale plan (the `plan-stale` problem) re-runs the preview and says so.

## S4.3.1 — Preview, confirm, apply

**State:** New

**Acceptance:**

- `S4.3.1: diff`: a plan with 2 items and 1 refusal renders the changed fields
  only, and the refusal under its code.
- `S4.3.1: empty diff`: an empty plan shows "Nothing to change" and no Apply.
- `S4.3.1: stale plan`: an apply that fails with `/problems/plan-stale` re-runs
  the preview once and tells the user.

## S4.3.2 — Undo from the result

**State:** New

**Acceptance:**

- `S4.3.2: undo toast`: a result with a `batch_id` shows a toast whose Undo runs
  the flow against the undo endpoint.
