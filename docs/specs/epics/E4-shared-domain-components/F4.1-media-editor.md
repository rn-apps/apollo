The one panel for editing one item, whether a library track or a staged inbox
file. It is the same from Songs, an album, a facet drill-down, Search, a
playlist, Errors and Inbox.

## Design

**Target and adapter** (`domain/media/`):

```ts
type MediaTarget = { kind: 'track'; id: number } | { kind: 'inbox'; path: string };
interface MediaAdapter {
  load(t: MediaTarget): Observable<MediaItem>;   // tags, field descriptors, check, artwork meta, audio url, quality
  capabilities(t: MediaTarget): Signal<Record<MediaOp, { available: boolean; reason?: string }>>;
  saveTags(t, changes, dryRun): Observable<Plan>;
  cleanTags(t, dryRun): Observable<Plan>;
  trim(t, range, dryRun): Observable<Plan | JobRef>;
  replace(t, source, dryRun): Observable<Plan | JobRef>;
  artwork: ArtworkAdapter;                         // F4.5
}
type MediaOp = 'tags' | 'clean' | 'artwork' | 'trim' | 'replace' | 'check';
```

A `MEDIA_ADAPTERS` provider maps `kind` to its adapter. A screen opens the
editor with a target, never with an adapter.

**Panel.** It is ngkit's side panel (F3.1) with `dirty` bound to the form's
dirty state.

- **Header.** Artwork thumbnail, title and artist, a quality badge, a check
  badge, and an audio preview.
- **Tabs (F3.4).** Each tab is built once:
    - **Tags.** A form generated from the field descriptors, using FieldControl,
      ChipsInput, AutocompleteInput and the identity editor for `artist` from
      [E6](../E6-tag-editing/index.md).
    - **Artwork.** The picker (F4.5).
    - **Trim.** A range on the waveform-less timeline of old `TrimPanel`.
    - **Replace.** A source path or URL, with the quality comparison.
    - **Checks.** The item's check results, with "Update tags from path" when
      paths disagree.
- **Footer.** Save, which goes through the dry-run flow (F4.3), and Clean tags.
  An operation the target lacks is disabled with its reason. Replace on an
  inbox target is an example.
- **Navigation.** Previous and next item within the opening list, by `↑`/`↓`
  with a modifier. The dirty guard applies.
- **URL.** `?item=track:42` or `?item=inbox:<path>` opens the panel, so it
  survives a reload.

There is one clean-tags state machine, one validation rendering (the Checks tab
plus the header badge), and one time formatter (F4.8).

## S4.1.1 — Target model and adapter contract

**State:** New

**Acceptance:**

- `S4.1.1: fake adapters`: `domain/testing/fake-media-adapter.ts` implements
  `MediaAdapter` for both kinds, with configurable capabilities.
- `S4.1.1: target codec`: `track:42` and `inbox:Artist/Album/01 x.flac` round
  trip through the URL codec, and paths with `:`, `/` and spaces survive.

## S4.1.2 — Panel shell, header and tabs

**State:** New

**Acceptance:**

- `S4.1.2: same panel both kinds`: opening a track target and an inbox target
  renders the same component, with the same header and tab set.
- `S4.1.2: disabled with reason`: an inbox target's Replace tab is disabled, and
  its accessible description is the adapter's reason.
- `S4.1.2: url opens`: navigating to `?item=track:42` opens the panel on that
  target, and closing it removes the parameter.

## S4.1.3 — Tags tab with dirty guard and dry-run save

**State:** New

**Acceptance:**

- `S4.1.3: generated form`: the fake's field descriptors render one control per
  field, in descriptor order, with plural fields as chips.
- `S4.1.3: dirty guard`: editing a field and pressing Esc asks before
  discarding.
- `S4.1.3: save via dry run`: Save calls `saveTags(dryRun=true)`, shows the
  plan's diff in the dry-run flow, and on confirm calls
  `saveTags(dryRun=false)`. The form is then clean, with the new values.

## S4.1.4 — Clean, trim, replace and checks tabs

**State:** New

**Acceptance:**

- `S4.1.4: clean once`: Clean tags previews and applies through the dry-run
  flow, and no other clean-tags state exists in `apps/web` (one grep in the
  spec).
- `S4.1.4: trim and replace submit jobs`: when the adapter returns a `JobRef`,
  the panel shows job progress (F4.4) for it.
- `S4.1.4: checks tab`: a check result with a path mismatch shows "Update tags
  from path", which runs through the dry-run flow.
