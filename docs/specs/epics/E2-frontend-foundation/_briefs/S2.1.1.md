## Goal

Load ngkit's styling in the existing Angular app and prove that the kit renders
before applying Apollo's palette.

## Settled

- [F2.1](../F2.1-web-dependencies.md) defines the matched ngkit release pins,
  style imports and dependencies for this story.
- [F2.4](../F2.4-theme.md) owns Apollo's token overrides.

## Current behaviour

`package.json:9` pins `@rn-forge/ng` at v0.3.0. `apps/web/src/styles.scss:1`
contains only a starter comment.

## Change

- Update root `package.json` and its lockfile for the dependencies in F2.1.
- Import ng-tailwind's token, base and Tailwind styles in
  `apps/web/src/styles.scss`. Preserve the starter API interaction.

## Tests first

- Add a Vitest spec beside the app named `S2.1.1: tokens load` that renders
  `RnfButton`. It fails with the kit dependencies absent.

## Result

- `package.json` and `pnpm-lock.yaml` pin ngkit v0.4.0. The lockfile uses the
  published GitHub release digests and passed pnpm's offline frozen lockfile
  check. A full install still requires the published tarballs and npm access.
- `apps/web/.postcssrc.json`, `apps/web/src/styles.scss` and
  `apps/web/src/app/ngkit.spec.ts` wire up Tailwind and exercise `RnfButton`.
- The four Angular tests passed using local v0.4.0 builds, and PostCSS compiled
  the stylesheet with ngkit tokens. The local builds differ from the published
  tarballs, so rerun the tests with the frozen install.
- Angular production builds abort in the sandbox with a macOS allocator error.
  The same error occurs on the unmodified scaffold. `task validate` is pending
  a successful install and build.
