# S2.1.2 — No known-vulnerable package in the npm lockfile

Brief for
[S2.1.2](../F2.1-web-dependencies.md#s212-no-known-vulnerable-package-in-the-npm-lockfile),
at the commit that adds this brief.

## Goal

Force patched versions of two transitive npm packages with pnpm overrides.

## Settled

- `js-yaml`: GHSA-52cp-r559-cp3m, GHSA-5p4m-2wfm-xmqj, GHSA-2883-xcg3-v3hh
  (high). Patched in 4.3.2 (and 3.15.2 for 3.x). Override
  `js-yaml@>=4.0.0 <4.3.2` to `^4.3.2`.
- `minimatch`: Dependabot alert #1 (medium), vulnerable `>=7.0.0 <11.0.1`,
  patched in 11.0.1. Override `minimatch@>=7.0.0 <11.0.1` to `^11.0.1`. This
  is a major bump for consumers of 10.x; if `task validate` or `task build`
  then fails because of it, remove only the minimatch override, keep js-yaml,
  and record the failure in `## Result` (the owner then decides).
- Overrides go in `pnpm-workspace.yaml` under a top-level `overrides:` map (pnpm
  12 reads them there). `pnpm-workspace.yaml` is repo-owned. Keep its existing
  keys.

## Current behaviour

- `pnpm-lock.yaml` has `js-yaml@4.2.0` (one dependent) beside 4.3.2, and
  `minimatch@10.2.5` and `minimatch@3.1.5`. 3.1.5 is outside the vulnerable
  range and stays.

## Change

1. Add to `pnpm-workspace.yaml`:

    ```yaml
    overrides:
      js-yaml@>=4.0.0 <4.3.2: ^4.3.2
      minimatch@>=7.0.0 <11.0.1: ^11.0.1
    ```

1. `task setup` (it installs with a frozen lockfile; if that refuses because the
   lockfile must change, report the exact error before anything else).

1. Confirm `pnpm-lock.yaml` no longer contains `js-yaml@4.2.0` or
   `minimatch@10.` (grep), and record it.
