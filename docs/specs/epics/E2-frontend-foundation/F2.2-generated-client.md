TypeScript types generated from the API's OpenAPI document, and the one
`core/api` layer that calls the API with them
([ADR-0020](../../../adr/ADR-0020.md)).

## Design

- `tasks/apollo.yml` (repo-owned, listed in `[tasks] includes`) defines
  `apollo:api-types`. It dumps `app.openapi()` to JSON without a server, and
  runs `openapi-typescript` (a root dev dependency) to write
  `apps/web/src/app/core/api/schema.d.ts`. The output is committed and carries
  a header saying it is generated.
- `core/api/api.ts` holds typed helpers over `HttpClient` for `paths` from the
  schema. Errors stay `HttpErrorResponse`, and are read with ngkit's problem
  helpers (`problemOf`, `problemTypeOf`, `hasProblemType`).
- There are no hand-written response interfaces anywhere in `apps/web`.
- Keep the connected home's `/livez` call inside `core/api` when centralising
  HTTP calls.

## S2.2.1 — Types generated and checked fresh

**State:** New

**Acceptance:**

- `task apollo:api-types` writes `schema.d.ts`. Running it twice produces no
  diff.
- `test_s2_2_1_1_types_fresh` (backend test): regenerating to a temporary file
  and comparing it with the committed `schema.d.ts` passes, and fails after a
  route signature changes.

## S2.2.2 — Typed API layer

**State:** New

**Acceptance:**

- `S2.2.2: typed get`: a spec using `HttpTestingController` calls
  `GET /v1/status` through `core/api` and gets the schema type.
- `S2.2.2: problem type`: a 409 `application/problem+json` response with `type`
  `/problems/conflict` is recognised by `hasProblemType`.
- An ESLint rule forbids `HttpClient` imports outside `core/api`.
