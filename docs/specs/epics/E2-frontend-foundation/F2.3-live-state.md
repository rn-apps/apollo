One connection to `/v1/events`, opened by the shell, feeding a status store and
an invalidation bus ([ADR-0008](../../../adr/ADR-0008.md)).

## Design

- `core/live/live-state.ts` (root provider) opens the stream with ngkit's
  `createEventStream`. It exposes signals: `status`, `jobs` (non-terminal, by
  id) and `connection` (`open`, `reconnecting` or `closed`).
- A terminal `job` frame is mapped by its job type to invalidation keys
  (`tracks`, `albums`, `facets`, `inbox`, `playlists`, `audit`, `errors`)
  through ngkit's `injectInvalidation<ApolloKey>()`. Screens refresh their
  resources on those keys.
- No screen polls.

## S2.3.1 — Stream to signals

**State:** New

**Acceptance:**

- `S2.3.1: frames update signals`: feeding a fake event source a `status` frame
  and two `job` frames updates `status()` and `jobs()`. A terminal frame
  removes its job from `jobs()`.
- `S2.3.1: one connection`: injecting the live state from two components opens
  one event source.

## S2.3.2 — Terminal frames invalidate resources

**State:** New

**Acceptance:**

- `S2.3.2: bulk edit invalidates`: a terminal `bulk_edit` frame emits the
  `tracks`, `albums` and `facets` keys, and a terminal `download` frame emits
  `inbox`.
- The job-type-to-keys map is one table, with a spec that covers every `JobType`
  in the generated schema.
