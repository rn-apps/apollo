The generic grid under apollo's track workspace
([F4.2](../E4-shared-domain-components/F4.2-track-workspace.md)) and every other
table in the app (jobs, history, playlists, Apple and review tables).

## Requirements for ngkit

- **Rows**: fixed-height virtual rows, on `@angular/cdk/scrolling`, with the
  height set by a token. Data comes through a data source that knows `total`,
  and fetches windows by offset, so it can scroll and seek across a 12,000-row
  list.
- **Columns**: defined by an id, a header, a cell template, a width (fixed or
  fractional), sortable or not, and an alignment. Column visibility, order and
  width are inputs and outputs, so the consumer can persist them.
- **Column manager**: a menu to show, hide and reorder columns.
- **Sort**: header clicks cycle through a configurable sequence over
  `{key, direction}` (F12.4), shown with `aria-sort`. Sort is an input and an
  output, so the URL can own it.
- **Selection**: none, single or multi. Shift-click or Shift-arrow selects a
  range, ⌘-click toggles, ⌘A selects all loaded rows or every row, and a
  `selection` output reports either the ids or "all matching".
- **Keyboard**: arrows move the focused row, Enter activates it, Space toggles
  its selection.
- **States**: empty, loading and error slots, using F3.3's primitives.
- **Performance gate**: 12,000 rows scroll at 60 fps in a production build on
  the owner's Mac. ngkit carries a benchmark page to measure it.
