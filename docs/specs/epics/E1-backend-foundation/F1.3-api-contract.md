The error hierarchy as RFC 9457 problems, paging, and the app-level contract
settings of [ADR-0020](../../../adr/ADR-0020.md).

## Design

`platform/errors.py` holds `ApolloError(AppException)`. Each subclass carries a
class-level `code` (hyphenated) and `status_code`:

`not-found` 404, `conflict` 409, `file-missing` 409, `write-failed` 500,
`validation` 422, `artwork-fetch` 502, `artwork-invalid-image` 422, `job-failed`
500, `icloud-sync-active` 409, `invalid-source` 422, `inbox-preview-stale` 409,
`trim-range` 422, `trim-result-too-short` 422, `capability-unavailable` 409,
`invalid-query` 422, `plan-stale` 409.

The old `ValidationError` had no `status_code` and fell back to 500. Here it is
422\. The hierarchy is registered with `register_hierarchy` only after every
module that defines an error has been imported.

Paging: every list answers with the kit's `Page[T]`. `apollo.db` lists use
`page_params` and `keyset`, and beets lists use apollo's own page token (F1.5).
S1.3.3 removed `platform/paging.py` and its `OffsetPage[T]`.

## S1.3.1 — Errors answer as problems

**State:** Closed (2026-11-20)

**Acceptance:**

- `test_s1_3_1_1_every_error_registered`: each `ApolloError` subclass renders as
  `application/problem+json`, with `type` `/problems/<code>` and its
  `status_code`.
- `test_s1_3_1_2_extensions`: an error that carries data exposes it as problem
  extensions, and has no `code` member.
- `test_s1_3_1_3_validation_422`: a request validation failure answers with the
  kit's validation problem and its field errors.
- `test_s1_3_1_4_unhandled_500`: an unhandled exception answers 500 with no
  detail, and its traceback is in the log.

## S1.3.2 — Paging shapes and app limits

**State:** Closed (2026-11-20)

**Acceptance:**

- `test_s1_3_2_1_offset_page`: `OffsetPage` serialises `items`, `offset`,
  `limit` and `total`, and clamps `limit` to 500.
- `test_s1_3_2_2_body_limit`: a 20 MiB request body is accepted, and a 26 MiB
  one gets the kit's 413 problem.
- `test_s1_3_2_3_no_cors`: no `Access-Control-Allow-Origin` header is sent.

S1.3.3 retired `test_s1_3_2_1_offset_page` on 2026-11-25.

## S1.3.3 — Remove offset paging

**State:** Closed (2026-11-25)

**Acceptance:**

- `platform/paging.py` and `OffsetPage` are gone, and nothing imports them
  ([ADR-0020](../../../adr/ADR-0020.md)).
- `test_s1_3_2_2_body_limit` and `test_s1_3_2_3_no_cors` pass unchanged.
