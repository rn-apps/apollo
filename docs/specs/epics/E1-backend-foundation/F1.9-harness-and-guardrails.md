Fixtures that every backend test uses, the rule that keeps the real library
safe, and the import contracts of [ADR-0019](../../../adr/ADR-0019.md).

## Design

- `tests/conftest.py`:
    - generates 0.2 s sine files (`mp3`, `m4a`, `flac`) with `ffmpeg`, once per
      session;
    - `fixture_library(tmp_path, spec)` builds a tagged library from a small spec
      of artists, albums and tracks;
    - `configured_env` points `APOLLO_STATE_DIR` and `APOLLO_LIBRARY_ROOT` into
      `tmp_path`;
    - `app_client` is an `httpx.AsyncClient` over the app, with its lifespan run.
- Marker `library_mutation`: a test that touches a non-fixture library carries
  it, and `addopts` deselects it. It is run only by the acceptance procedure
  of [E15](../E15-acceptance-and-cutover/index.md).
- `.importlinter` (below kiln's block) holds a `layers` contract over
  `apollo_api.{routes, jobs, workflows, proposals | validation | apple, index, media, platform}`.
- The old 172 MB `legacy-catalog.sqlite3` fixture is not ported.

## Open question: SonarCloud

The repo publishes under GitHub org `rn-apps`, but kiln hardcodes the SonarCloud
organisation as `rn-forge`. The rendered `sonar-project.properties` therefore
says `sonar.organization=rn-forge` and `sonar.projectKey=rn-forge_apollo`. This
is a kiln finding, recorded in kiln F16.5.

Before the first CI run, the owner chooses one of:

- an `rn-apps` SonarCloud organisation, once kiln can render it;
- `[ci] sonar = false` until then.

The `[ci] sonar = true` default from the scaffold stays until the owner decides.
