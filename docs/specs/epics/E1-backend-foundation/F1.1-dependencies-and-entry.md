The API package's runtime dependencies, its console entry, and `ffmpeg` in CI.

## Context

The fresh scaffold (2026-11-15) shows three kiln defects:

- kiln pins `rn-forge-commons>=0.8.1,<0.9`. That excludes commons 0.9.0, where
  `ThreadActor`, `TaskPool.map_settled` and the new `PathUtils` helpers
  shipped.
- kiln pins `@rn-forge/ng` to v0.3.0, while ngkit is at v0.4.0.
- `[project.scripts] apollo-api = "apollo_api:main"` names a `main` that kiln
  does not seed.

Under [ADR-0002](../../../adr/ADR-0002.md) each one is fixed in kiln, in kiln
F16.5, so the next repository is scaffolded right:

- S16.5.4 moves the pykit floors to release 8;
- S16.5.5 moves the ngkit pin to v0.4.0;
- S16.5.6 removes the web API member's console script.

`apps/api/pyproject.toml` and `package.json` are seeded files, and this repo
owns them. Moving `[kiln] ref` does not rewrite them, so this repo makes the
same edits by hand: S1.1.1 does the floors, S1.1.2 the script, and
[S2.1.1](../E2-frontend-foundation/F2.1-web-dependencies.md) the ngkit pin.
kiln's `rn-forge-deps` check requires only a ceiling on each range, so the
hand-raised floors pass `kiln doctor` before kiln's own fix lands.

The edits, against the 2026-11-15 scaffold:

| File | From | To |
| -- | -- | -- |
| `apps/api/pyproject.toml` | `rn-forge-commons>=0.8.1,<0.9` | `rn-forge-commons>=0.9.0,<0.10` |
| `apps/api/pyproject.toml` | `rn-forge-cli>=0.1.2,<0.2` | `rn-forge-cli>=0.1.3,<0.2` |
| `apps/api/pyproject.toml` | `rn-forge-web>=0.3.0,<0.4` | `rn-forge-web>=0.3.1,<0.4` |
| `apps/api/pyproject.toml` | `rn-forge-fastapi>=0.4.0,<0.5` | `rn-forge-fastapi[sse]>=0.4.1,<0.5` |
| `apps/api/pyproject.toml` | `apollo-api = "apollo_api:main"` | `apollo-api = "apollo_api.cli:main"` (S1.1.2) |
| root `package.json` | `…/v0.3.0/rn-forge-ng-0.3.0.tgz` | `…/v0.4.0/rn-forge-ng-0.4.0.tgz` (S2.1.1) |

The kiln pin `7b0883` (2026-11-19) re-rendered the four rn-forge floors past
this table (commons 0.10.0, cli 0.2.0, web 0.3.2, fastapi 0.5.0). S1.1.1 keeps
them and adds only the `[sse]` extra.

Until S1.1.2 lands, the seeded script `apollo-api` exists but fails with
`ImportError` when run. Nothing calls it: `task api:dev` runs uvicorn directly.

## Design

Runtime dependencies added to `apps/api/pyproject.toml`, on top of what kiln
renders:

| Package | Why |
| -- | -- |
| `rn-forge-sqlalchemy[migrations]>=0.2.3,<0.3` | async engine, models, embedded migrations ([ADR-0021](../../../adr/ADR-0021.md)) |
| `rn-forge-fastapi[sse]` (extra on the rendered pin) | `sse_response` ([ADR-0008](../../../adr/ADR-0008.md)) |
| `beets>=2.13.1`, `mediafile`, `mutagen` | index and tags |
| `pydantic-settings` | `APOLLO_*` settings |
| `httpx` | artwork URL fetch (moved from dev to runtime) |
| `python-multipart` | artwork upload |
| `yt-dlp` | downloads ([E9](../E9-downloads-and-proposals/index.md)) |
| `uvicorn[standard]` | the served process (moved from dev to runtime) |

Accepting this feature approves these dependencies.

## S1.1.1 — Runtime dependencies resolve on current pykit

**State:** Closed (2026-11-19)

**Acceptance:**

- `apps/api/pyproject.toml` keeps the rendered rn-forge floors, adds the `[sse]`
  extra to `rn-forge-fastapi`, and adds the packages in the Design table.
  `task setup` resolves them, and `uv.lock` has `rn-forge-commons` at 0.10.0
  or later.
- `test_s1_1_1_1_kit_symbols_import`: `ThreadActor`, `TaskPool`, `PathUtils` and
  `rn_forge.fastapi.sse.sse_response` all import.
- `kiln doctor` raises no rn-forge-deps finding.
- The licence check denies GPL as before, with one exception: `mutagen` and
  `Unidecode` (both GPL-2.0-or-later, required by beets and mediafile) are in
  `[ci.checks] licenses` ignore. Apollo runs locally and is not distributed;
  publishing it would need a GPL-compatible licence (owner, 2026-11-19).

## S1.1.2 — `apollo-api serve` runs the app

**State:** Closed (2026-11-20)

**Acceptance:**

- `apollo_api.cli:main` is a `rn_forge.cli.CliApp` with one command, `serve`. It
  runs uvicorn on `APOLLO_BIND_HOST` (default `127.0.0.1`) and port 8000, and
  the script entry points at it. This replaces the broken seeded
  `apollo_api:main` (kiln S16.5.6); the repo still owns the entry point.
- `test_s1_1_2_1_serve_builds_uvicorn_config`: `serve` builds the uvicorn config
  from settings and does not bind a socket in the test.
- `task api:dev` still serves `app` with reload.

## S1.1.3 — CI has ffmpeg and ffprobe

**State:** Closed (2026-11-20)

**Acceptance:**

- A repo-owned composite action, `.github/actions/media-tools/action.yml`,
  installs `ffmpeg` and is listed in `[ci.hooks] setup`. `task kiln:apply`
  renders it into the setup action.
- A CI run on a pull request shows `ffprobe -version` in the setup step.
- Verified on PR #4 (2026-11-20): the setup step printed
  `ffprobe version 8.0.1-3ubuntu2`.

## S1.1.4 — `rn-forge-sqlalchemy` resolves

**State:** New · **Depends on:** kiln
[S16.5.8](https://github.com/rn-forge/kiln/blob/main/docs/specs/epics/E16-init-adopts-by-overwrite/F16.5-rebuild-and-port.md)

Split from S1.1.1 on 2026-11-19: kiln's `python-web-app` archetype does not
allow `rn-forge-sqlalchemy`, so `kiln doctor` rejects it until kiln S16.5.8
widens the allowed set.

**Acceptance:**

- `[kiln] ref` is moved past kiln S16.5.8 and `task kiln:apply` is run.
- `apps/api/pyproject.toml` adds `rn-forge-sqlalchemy[migrations]>=0.2.4,<0.3`,
  and `kiln doctor` raises no rn-forge-deps finding.
- `test_s1_1_4_1_sqlalchemy_symbols_import`: `create_sqlite_engine` and
  `rn_forge.sqlalchemy.migrate.run_migrations` import.
