# S1.3.1 — Errors answer as problems

Brief for [S1.3.1](../F1.3-api-contract.md#s131-errors-answer-as-problems), at
`f0e56e3` plus the commit that adds this brief.

## Goal

Replace the starter `ItemNotFound` with the `ApolloError` hierarchy, registered
with the kit so every error answers as RFC 9457 `application/problem+json` with
`type` `/problems/<code>`. Ported from the old
`rn_backup/apollo/apps/api/src/apollo/errors.py` (hierarchy) and the three
handlers in `main.py` (lines 202-250, which this story replaces with the kit's).

## Settled

- Codes and statuses are the table in the feature's Design
  ([F1.3](../F1.3-api-contract.md#design)), copied below. They differ from the
  old module in three places, on purpose: codes are hyphenated; `validation`
  has an explicit 422 (the old one fell back to 500); `invalid-query` is 422
  (old 400), `artwork-fetch` is 502 (old 422), `invalid-source` is 422 (old
  409\) and `capability-unavailable` is 409 (old 422).
- `type` is `/problems/<code>`, so the registry is
  `default_registry(type_base="/problems/")`
  ([ADR-0020](../../../../adr/ADR-0020.md)).
- Problem extensions are camelCase (owner, 2026-11-20; pykit rule
  `casing.response-bodies-are-camel-case`, "Problem extensions follow the
  rule"). An error's `error_data` keys are snake_case in Python, so
  `problem_extensions()` camelCases them: `track_id=7` is `trackId` on the
  wire.
- Extensions come only from an error below 500; the kit drops them for 5xx
  (`ProblemRegistry.build`). That is intended: a 5xx body says nothing about
  the cause.
- The problem has no `code` member: the code is in `type`.
- A request validation failure keeps the kit's own row: `type`
  `/problems/validation-error`, 422, with an `errors` list of
  `{"pointer": "/displayName", "detail": "This field is required."}`. It is
  not the `validation` code, which is for `ValidationError` raised by
  application code.
- An unhandled exception is the kit's fallback: 500, `type`
  `/problems/internal-error`, `detail` `An unexpected error occurred.`. Its
  traceback reaches the log through `log_server_errors`, which S1.2.2 already
  wired in `create_app`; this story adds no logging code.
- The hierarchy is registered once, in `create_app`, after every error module is
  imported (`register_hierarchy` walks only subclasses already imported).
- The starter `apollo_api/errors.py` (`ItemNotFound`) is deleted; the starter
  `GET /v1/items/{item_id}` raises `NotFoundError` instead.

The hierarchy (parent in brackets; every class sets `code` and `status_code`
itself, even when it equals its parent's):

| Class | Parent | `code` | `status_code` |
| -- | -- | -- | -- |
| `ApolloError` | `AppException` | `internal-error` | 500 |
| `NotFoundError` | `ApolloError` | `not-found` | 404 |
| `ConflictError` | `ApolloError` | `conflict` | 409 |
| `FileMissingError` | `ConflictError` | `file-missing` | 409 |
| `WriteFailedError` | `ApolloError` | `write-failed` | 500 |
| `ValidationError` | `ApolloError` | `validation` | 422 |
| `ArtworkFetchError` | `ApolloError` | `artwork-fetch` | 502 |
| `ArtworkInvalidImageError` | `ValidationError` | `artwork-invalid-image` | 422 |
| `JobFailedError` | `ApolloError` | `job-failed` | 500 |
| `ICloudSyncActiveError` | `ConflictError` | `icloud-sync-active` | 409 |
| `InvalidSourceError` | `ApolloError` | `invalid-source` | 422 |
| `InboxPreviewStaleError` | `ConflictError` | `inbox-preview-stale` | 409 |

Design are the other rows.

## Current behaviour

- `apps/api/src/apollo_api/errors.py` holds only
  `class ItemNotFound(Exception)`.
- `apps/api/src/apollo_api/app.py:24` builds
  `registry = default_registry().register(ItemNotFound, NOT_FOUND)` at import;
  `create_app` (line 49) passes it as `AppConfig(registry=registry, log=...)`.
  With no `type_base`, every problem's `type` is `about:blank`.
- `apps/api/src/apollo_api/routes.py:11,30` imports and raises `ItemNotFound`.
- There is no `apollo_api/platform/errors.py`. With the tests below written and
  nothing else changed, collection of `test_s1_3_1_errors.py` fails with
  `ModuleNotFoundError: No module named 'apollo_api.platform.errors'`, so all
  four tests error.
- `apps/api/tests/test_app.py::test_an_application_error_is_a_problem_response`
  passes now and must still pass: `GET /v1/items/42` is 404 with
  `application/problem+json`.

## Change

1. Create `apps/api/src/apollo_api/platform/errors.py` with a module docstring
   and a docstring on every class:

    ```python
    from __future__ import annotations

    from collections.abc import Mapping
    from typing import Any

    from rn_forge.commons import AppException


    def _camel(key: str) -> str:
        head, *tail = key.split("_")
        return head + "".join(part.capitalize() for part in tail)


    class ApolloError(AppException):
        """Base domain failure: a stable problem code and an HTTP status."""

        code = "internal-error"
        status_code = 500

        def problem_extensions(self) -> Mapping[str, Any]:
            """Publish ``error_data`` as problem extensions, keys camelCased."""
            return {_camel(key): value for key, value in self.error_data.items()}
    ```

    Then one subclass per row of the table above, in that order, each with a
    one-line docstring and exactly the two class attributes `code` and
    `status_code` (strings and ints as in the table). Take each docstring from
    the old class in `rn_backup/apollo/apps/api/src/apollo/errors.py`;
    `ArtworkFetchError` and `InvalidSourceError` keep theirs, `PlanStaleError`
    is "A plan was made against state that has since changed."
    `platform/errors.py` imports nothing from `apollo_api`.

1. `apps/api/src/apollo_api/app.py`:

    - Remove `from rn_forge.web import NOT_FOUND, default_registry`, the
      `ItemNotFound` import and the module-level `registry = ...`.

    - Add `from rn_forge.web import ProblemRegistry, default_registry` and
      `from apollo_api.platform.errors import ApolloError`.

    - Add

        ```python
        def build_registry() -> ProblemRegistry:
            """Map every `ApolloError` to its problem; call after all error modules import."""
            return default_registry(type_base="/problems/").register_hierarchy(ApolloError)
        ```

    - In `create_app`, `AppConfig(registry=build_registry(), log=...)`; leave
      everything else in `create_app` and `lifespan` as it is.

1. `apps/api/src/apollo_api/routes.py`: import `NotFoundError` from
   `apollo_api.platform.errors` in place of `ItemNotFound`; `get_item` raises
   `NotFoundError("item {} not found", item_id)`; its docstring says
   `Fail with `NotFoundError`: the starter holds no items.`

1. Delete `apps/api/src/apollo_api/errors.py`.

- **Leave alone:** `lifespan`, the `log=` argument, `max_body_bytes` (S1.3.2),
  `platform/settings.py`, `platform/runtime.py`, `cli.py`, `.importlinter`,
  every kiln-generated file.

## Tests first

Create `apps/api/tests/test_s1_3_1_errors.py`. Annotate every function (pyright
strict). Imports: `Iterator`, `Path`, `pytest`,
`from fastapi.testclient import TestClient`,
`from rn_forge.web import PROBLEM_MEDIA_TYPE, WireModel`,
`from apollo_api.app import create_app`,
`from apollo_api.platform.errors import ApolloError, NotFoundError, WriteFailedError`.
Never define an `ApolloError` subclass in the tests: it would join every later
`create_app()` registry.

Helpers:

- `_subclasses(base: type[ApolloError]) -> Iterator[type[ApolloError]]`: yields
  each `base.__subclasses__()` entry and, recursively, its subclasses.
- `_raiser(error: type[ApolloError])`: returns
  `async def raise_it() -> None: raise error("failed")` (a factory, so each
  route binds its own class).
- `EXPECTED: dict[str, int]` with the 16 code-to-status pairs of the table
  (every row but `ApolloError`).

Tests:

- `test_s1_3_1_1_every_error_registered`: `application = create_app()`; for each
  class from `_subclasses(ApolloError)`,
  `application.add_api_route(f"/raise/{cls.code}", _raiser(cls))`. Assert
  `{cls.code: cls.status_code for cls in subclasses} == EXPECTED`. With
  `TestClient(application, raise_server_exceptions=False)`, `GET` each route
  and assert: status is `cls.status_code`; `content-type` starts with
  `PROBLEM_MEDIA_TYPE`; `body["type"] == f"/problems/{cls.code}"`;
  `body["status"] == cls.status_code`. Also assert one `ApolloError("failed")`
  route (`/raise/base`) answers 500 with `type` `/problems/internal-error`.

## Out of scope

- Raising these errors from real routes: later features do.
- A custom handler, an error envelope or an `X-Request-ID` header; the kit's
  handlers and `traceId` replace them
  ([ADR-0020](../../../../adr/ADR-0020.md)).
- Any `error_code` use (the `AppException` integer): leave its default.
- Paging and the body limit (S1.3.2), and `validation-error`'s field shape,
  which is the kit's.
