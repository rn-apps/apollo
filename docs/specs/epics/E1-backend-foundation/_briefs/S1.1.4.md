# S1.1.4 — `rn-forge-sqlalchemy` resolves

Brief for
[S1.1.4](../F1.1-dependencies-and-entry.md#s114-rn-forge-sqlalchemy-resolves),
at `27c9acd` plus the commit that adds this brief.

## Goal

Move apollo's kiln pin past kiln S16.5.8, which allows `rn-forge-sqlalchemy` in
web archetypes, and add the dependency.

## Settled

- The new pin is kiln `3a11258b9a09cefb9f4818a74317708564798e4c` (S16.5.8 on
  `feature/v1`).
- `task kiln:pin -- <sha>` sets `[kiln] ref` in `.rn-forge/kiln/config.toml` and
  runs `kiln apply` at the new ref. Every file it re-renders is kiln's; accept
  them as rendered and list them in `## Result`. The move spans several kiln
  commits (for example the root `dev` verb from kiln S16.5.7), so more than
  the dependency check may change.
- S16.5.8 moved kiln's `rn-forge-fastapi` pin to 0.5.1; raise the floor to
  match, so `kiln doctor` raises no floor warning.
- The dependency is `rn-forge-sqlalchemy[migrations]>=0.2.4,<0.3`, appended
  after `uvicorn[standard]` in `apps/api/pyproject.toml`.

## Current behaviour

- `[kiln] ref = "7b0883119be5d89027bb0fb78d7e5233377b0cee"`.
- `apps/api/pyproject.toml` has `rn-forge-fastapi[sse]>=0.5.0,<0.6` and no
  `rn-forge-sqlalchemy`.
- With the test below written and nothing else changed, it fails with
  `ModuleNotFoundError: No module named 'rn_forge.sqlalchemy'`.

## Change

1. `task kiln:pin -- 3a11258b9a09cefb9f4818a74317708564798e4c`.
1. `apps/api/pyproject.toml`: change the fastapi pin to
   `rn-forge-fastapi[sse]>=0.5.1,<0.6` and append
   `"rn-forge-sqlalchemy[migrations]>=0.2.4,<0.3",` after
   `"uvicorn[standard]>=0.54.0",`. Change nothing else.
1. `task setup` to update `uv.lock`.

## Tests first

Create `apps/api/tests/test_s1_1_4_dependencies.py` with
`test_s1_1_4_1_sqlalchemy_symbols_import`: inside the test body, import
`create_sqlite_engine` from `rn_forge.sqlalchemy` and `run_migrations` from
`rn_forge.sqlalchemy.migrate`, and assert both are callable.
