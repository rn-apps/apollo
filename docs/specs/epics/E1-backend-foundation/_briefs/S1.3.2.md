# S1.3.2 — Paging shapes and app limits

Brief for [S1.3.2](../F1.3-api-contract.md#s132-paging-shapes-and-app-limits),
at `f0e56e3` plus the commit that adds this brief.

## Goal

Add `OffsetPage[T]`, the response shape for beets-backed lists, raise the
request body limit from the kit's 1 MiB to 25 MiB for artwork uploads, and pin
that no CORS header is sent. Ported from the old paged envelope (`page`,
`page_size`, `total` in
`rn_backup/apollo/apps/api/src/apollo/schemas/errors.py`, `TrackErrorListOut`);
the old `index/paging.py` is a beets `LIMIT`/`OFFSET` reader and belongs to
F1.5, not here.

## Settled

- `OffsetPage[T]` lives in `apollo_api/platform/paging.py`, derives from
  `rn_forge.web.WireModel`, and has exactly `items: list[T]`, `offset: int`,
  `limit: int`, `total: int`. All four names are single words, so camelCase on
  the wire changes nothing; the shape follows the casing rule of E1 (owner,
  2026-11-20) by deriving from `WireModel`.
- The limit is clamped to 500 by the model itself: constructing it with a larger
  `limit` stores 500. The constant is `MAX_LIMIT = 500`.
- Nothing else is clamped or validated: no bound on `offset`, `total` or a lower
  `limit`, and no query-parameter dependency. The routes that read `offset`
  and `limit` from the query arrive with F1.5.
- The body limit is `25 * 1024 * 1024` bytes, passed as
  `AppConfig(max_body_bytes=...)` ([ADR-0020](../../../../adr/ADR-0020.md)).
  The kit's middleware rejects a declared `Content-Length` over it with its
  own 413 problem (`application/problem+json`, `status` 413); its `type` is
  the kit's `about:blank`, which is not changed here.
- CORS is off by default in the kit (`AppConfig.cors` is `None`) and stays off;
  the test only guards it.
- `apollo.db` lists use the kit's `Page` and `page_params` unchanged; there is
  no wrapper for them.

## Current behaviour

- `apps/api/src/apollo_api/platform/paging.py` does not exist. With the tests
  below written and nothing else changed, collection of
  `test_s1_3_2_paging.py` fails with
  `ModuleNotFoundError: No module named 'apollo_api.platform.paging'`, so all
  three tests error.
- `apps/api/src/apollo_api/app.py:49-62` (`create_app`) builds
  `AppConfig(registry=..., log=...)` with no `max_body_bytes`, so the kit's
  default of 1 MiB applies: a 20 MiB `POST` already answers 413. With the
  import line of the test file removed, `test_s1_3_2_2_body_limit` would fail
  on `assert response.status_code == 200` (got 413).
- No CORS middleware is installed, so `test_s1_3_2_3_no_cors` would already pass
  with the import removed; it is a regression guard, not a red test.

## Change

1. Create `apps/api/src/apollo_api/platform/paging.py` (module docstring and a
   class docstring; it imports nothing from `apollo_api`):

    ```python
    from __future__ import annotations

    from typing import Final

    from pydantic import field_validator
    from rn_forge.web import WireModel

    MAX_LIMIT: Final = 500
    """The largest page an offset list serves."""


    class OffsetPage[T](WireModel):
        """One page of a beets-backed list: a window and the full count."""

        items: list[T]
        offset: int
        limit: int
        total: int

        @field_validator("limit")
        @classmethod
        def _clamp_limit(cls, value: int) -> int:
            return min(value, MAX_LIMIT)
    ```

1. `apps/api/src/apollo_api/app.py`: add
   `MAX_BODY_BYTES: Final = 25 * 1024 * 1024` (with
   `from typing import Final`) and pass `max_body_bytes=MAX_BODY_BYTES` in the
   `AppConfig(...)` call of `create_app`. Add one sentence about the limit to
   the module docstring.

- **Leave alone:** the registry and error classes (S1.3.1), `lifespan`, `log=`,
  `routes.py`, `cors` (do not pass it), `security_headers`, every
  kiln-generated file.

## Tests first

Create `apps/api/tests/test_s1_3_2_paging.py`. Annotate every function (pyright
strict). Imports: `from fastapi import Request`,
`from fastapi.testclient import TestClient`,
`from rn_forge.web import PROBLEM_MEDIA_TYPE`,
`from apollo_api.app import create_app`,
`from apollo_api.platform.paging import OffsetPage`.

- `test_s1_3_2_1_offset_page`:
  `page = OffsetPage[int](items=[1, 2], offset=4, limit=1000, total=9)`:
  `page.limit == 500` and
  `page.model_dump() == {"items": [1, 2], "offset": 4, "limit": 500, "total": 9}`.
  Then `OffsetPage[int](items=[], offset=0, limit=50, total=0).limit == 50`.
  Then add a route to `create_app()`:
  `@application.get("/page", response_model=OffsetPage[int])` returning
  `OffsetPage[int](items=[1], offset=0, limit=10, total=1)`; `GET` answers 200
  with JSON `{"items": [1], "offset": 0, "limit": 10, "total": 1}`.
- `test_s1_3_2_2_body_limit`: `application = create_app()` and a route
  `@application.post("/echo")`,
  `async def echo(request: Request) -> dict[str, int]` returning
  `{"size": len(await request.body())}`. With
  `TestClient(application, raise_server_exceptions=False)`: a `POST` with
  `content=b"x" * (20 * 1024 * 1024)` answers 200 with
  `{"size": 20 * 1024 * 1024}`; a `POST` with
  `content=b"x" * (26 * 1024 * 1024)` answers 413 with `content-type` starting
  `PROBLEM_MEDIA_TYPE` and `response.json()["status"] == 413`.
- `test_s1_3_2_3_no_cors`: a `GET /livez` with header
  `Origin: http://example.com` answers 200 and
  `"access-control-allow-origin" not in response.headers`. Repeat with an
  `OPTIONS /livez` carrying `Access-Control-Request-Method: GET` in addition;
  the header is still absent.

## Out of scope

- A dependency that reads `offset` and `limit` from the query, a `total` query,
  and any beets paging (F1.5).
- A wrapper around the kit's `Page` or `page_params` for `apollo.db` lists.
- Setting a CORS policy, changing `security_headers`, or giving the 413 problem
  a `/problems/` type.
- `S1.3.1`'s files (`platform/errors.py`, the registry).
