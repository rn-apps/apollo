# S1.1.1 — Runtime dependencies resolve on current pykit

Brief for
[S1.1.1](../F1.1-dependencies-and-entry.md#s111-runtime-dependencies-resolve-on-current-pykit),
at `4a69db7` plus the commit that adds this brief.

## Goal

Add the API's runtime dependencies to `apps/api/pyproject.toml`, so the kit
symbols later features build on import, with one recorded licence exception for
beets' GPL dependencies.

## Settled

- The four rn-forge floors kiln rendered stay as they are:
  `rn-forge-commons>=0.10.0,<0.11`, `rn-forge-cli>=0.2.0,<0.3`,
  `rn-forge-web>=0.3.2,<0.4`, `rn-forge-fastapi>=0.5.0,<0.6`. Only the `[sse]`
  extra is added to the fastapi pin.
- The owner approved the Design-table dependencies by accepting F1.1, and on
  2026-11-19 approved a licence exception for `mutagen` and `Unidecode`
  (GPL-2.0-or-later; beets requires `Unidecode` and `mediafile`, which
  requires `mutagen`). The deny list itself is unchanged.
- `apps/api/pyproject.toml` is a seeded file this repo owns, so it is edited by
  hand. `.rn-forge/kiln/config.toml` is the only way to change the licence
  check: `tasks/python.yml` and `tasks/node.yml` are kiln-generated and are
  re-rendered by `task kiln:apply`, never edited.
- The console script (`[project.scripts]`) is S1.1.2's, and `ffmpeg` in CI is
  S1.1.3's. Leave both alone.

## Current behaviour

- `apps/api/pyproject.toml` `dependencies` holds only the four rn-forge pins
  above, without any extra. `[dependency-groups] dev` holds `"httpx>=0.28.1"`
  and `"uvicorn>=0.30"`.
- `rn_forge.commons` already exports `ThreadActor`, `TaskPool` and `PathUtils`.
  `rn_forge.sqlalchemy` is not installed. `rn_forge.fastapi.sse` exists but
  imports `sse_starlette`, which is not installed without the `[sse]` extra.
- `.rn-forge/kiln/config.toml` has an empty `[ci.checks]` table, so the rendered
  `python:lint:licenses` task denies `GPL`, `GPL-*`, `AGPL`, `AGPL-*` and
  `UNKNOWN`, ignoring only `api`, `apollo`, `apollo-api` and `text-unidecode`.
  Adding beets without the exception makes `task lint` fail on `mutagen` and
  `Unidecode`.
- With the test below written and nothing else changed, it fails with
  `ModuleNotFoundError: No module named 'rn_forge.sqlalchemy'`.

## Change

1. `apps/api/pyproject.toml`, `[project] dependencies`: change the fastapi pin
   to `"rn-forge-fastapi[sse]>=0.5.0,<0.6"` and append, in this order:

    ```toml
    "rn-forge-sqlalchemy[migrations]>=0.2.4,<0.3",
    "beets>=2.13.1",
    "mediafile>=0.17.0",
    "mutagen>=1.48.1",
    "pydantic-settings>=2.16.3",
    "httpx>=0.28.1",
    "python-multipart>=0.0.34",
    "yt-dlp>=2026.10.26",
    "uvicorn[standard]>=0.54.0",
    ```

1. Same file, `[dependency-groups] dev`: remove `"httpx>=0.28.1"` and
   `"uvicorn>=0.30"` (they are runtime dependencies now), leaving `dev = []`.
   Keep the table.

1. `.rn-forge/kiln/config.toml`: under the existing `[ci.checks]` header, add

    ```toml
    licenses = { deny = ["GPL", "GPL-*", "AGPL", "AGPL-*", "UNKNOWN"], ignore = ["mutagen", "Unidecode"] }
    ```

    Change nothing else in that file. Then run `task kiln:apply` so the licence
    tasks are re-rendered. The ignore list is matched on the exact name
    `pip-licenses` reports; if `task lint` still lists `mutagen` or `Unidecode`
    under a different spelling, use that spelling and record it as a deviation.

1. Run `task setup` so `uv.lock` resolves the new dependencies.

## Tests first

Create `apps/api/tests/test_s1_1_1_dependencies.py` with one test,
`test_s1_1_1_1_kit_symbols_import`. Import inside the test body (not at module
top), so collection succeeds and the test itself fails before the change:

- from `rn_forge.commons`: `ThreadActor`, `TaskPool`, `PathUtils`;
- from `rn_forge.sqlalchemy`: `create_sqlite_engine`;
- from `rn_forge.sqlalchemy.migrate`: `run_migrations`;
- from `rn_forge.fastapi.sse`: `sse_response`.

Assert each is callable. Before the change it fails with
`ModuleNotFoundError: No module named 'rn_forge.sqlalchemy'`.

## Validation

Run every `task` command from the worktree root as
`env -u VIRTUAL_ENV NX_WORKSPACE_ROOT_PATH="$PWD" task <verb>`; otherwise the
toolchain runs the main checkout instead of this worktree.

While iterating, run `task test`.

1. `task kiln:apply`
1. `task setup`
1. `task format`
1. `task validate` (lint, including the licence check, the dependency audit and
   `kiln doctor`, then typecheck, every test suite and the docs build)

If the dependency audit (`pip-audit`) or the licence check reports a package
other than `mutagen` or `Unidecode`, stop and report it; do not add ignores.

## Review re-run

Run `task test`, then `task lint`.

## Rules

- Use `task` for the toolchain. Never call `uv`, `pytest`, `ruff`, `pyright`,
  `pnpm` or `kiln` directly.
- Edit no kiln-generated file (each carries a provenance header naming kiln);
  configuration goes through `.rn-forge/kiln/config.toml` and
  `task kiln:apply`.
- Add no dependency beyond the list above. Do not commit or push.
