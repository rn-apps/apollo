# S1.9.2 — Layering contract

Brief for [S1.9.2](../F1.9-harness-and-guardrails.md#s192-layering-contract), at
`cb2a13b` plus the commit that adds this brief.

## Goal

`task lint` enforces the backend's one-way layering
([ADR-0019](../../../../adr/ADR-0019.md),
[backend architecture](../../../../architecture/backend.md#layers)) with an
import-linter `layers` contract.

## Settled

- The contract goes in `.importlinter` **below** the `# END rn-forge kiln` line,
  as its own section; the header says a repo's own contracts go there. The
  kiln block above it is not touched.
- Layers, highest first (a higher layer may import a lower one, never the
  reverse): `routes`, `jobs`, `workflows`, `proposals | validation | apple`
  (independent of each other), `index`, `media`, `platform`.
- Only `routes` and `platform` exist today. Every other layer is optional,
  written in parentheses, so the contract holds now and binds each package as
  it appears. `app`, `cli` and `errors` are composition and starter modules
  outside the layers.
- import-linter is 2.16; it supports `containers`, optional `(layer)` and
  independent `a | b` layers.

## Current behaviour

- `.importlinter` holds only kiln's block: `[importlinter]` with
  `root_package = apollo_api` and the `frameworks-come-from-rn-forge`
  forbidden contract, ending at `# END rn-forge kiln`.
- `apollo_api.platform` imports nothing from `apollo_api.routes`, so the new
  contract passes on today's code.

## Change

1. Append to `.importlinter`, after the `# END rn-forge kiln` line and a blank
   line:

    ```ini
    [importlinter:contract:layers]
    name = apollo_api is layered one way (ADR-0019)
    type = layers
    containers =
        apollo_api
    layers =
        routes
        (jobs)
        (workflows)
        (proposals) | (validation) | (apple)
        (index)
        (media)
        platform
    ```
