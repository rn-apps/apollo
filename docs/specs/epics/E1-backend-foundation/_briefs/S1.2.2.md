# S1.2.2 — Logging to the runtime tree

Brief for
[S1.2.2](../F1.2-settings-and-runtime.md#s122-logging-to-the-runtime-tree), at
`1639856` plus the commit that adds this brief.

## Goal

At startup the API prepares the runtime tree and initialises `AppLogger` once,
with root logger `apollo` and a log file under `logs/`. 5xx problems are logged
there with their traceback. Ported from the old lifespan in
`rn_backup/apollo/apps/api/src/apollo/main.py` (lines 91-104).

## Settled

- The lifespan lives in `apollo_api/app.py`, the composition root. It calls
  `prepare(get_settings())` from S1.2.1, then `AppLogger.initialize`.
- `AppLogger` writes a plain `logging.FileHandler` and appends a datestamp to a
  file path given without a suffix. `file=str(settings.logs_path / "apollo")`
  therefore writes `logs/apollo<datestamp>`, one file per day, as the old app
  did. That is what "rotating" means in the acceptance.
- `force_reconfigure=True`, so a second startup in the same process (tests,
  reload) logs to the current settings' file.
- Level `logging.INFO`; `update_loggers` as in the old app:
  `{"beets": WARNING, "uvicorn.access": WARNING, "uvicorn.error": INFO}` (no
  `alembic`: no migrations yet).
- 5xx problems:
  `AppConfig(log=log_server_errors(AppLogger.get_logger("apollo.http")))`
  (`log_server_errors` from `rn_forge.fastapi.problem`), so the records sit
  under the `apollo` root logger and reach the file.
- `app.py` gets a `create_app() -> FastApiApp` factory, and `app = create_app()`
  stays the module attribute `task api:dev` serves.
- `.apollo/` and `.env` are added to `.gitignore` above the
  `# BEGIN rn-forge kiln` line (the lines between the markers are kiln's).

## Current behaviour

- `apps/api/src/apollo_api/app.py` builds
  `app = FastApiApp(AppConfig(registry=registry), routers=(router,), title="apollo")`
  at import, with no lifespan and no `log`.
- Nothing calls `prepare()`; nothing initialises logging; `.gitignore` does not
  mention `.apollo/` or `.env`.
- `apps/api/tests/test_app.py` builds `TestClient(app, ...)` without a `with`
  block, so the lifespan never runs there; it stays that way.
- With the tests below written and nothing else changed, collection fails with
  `ImportError: cannot import name 'create_app' from 'apollo_api.app'`.

## Change

1. `apps/api/src/apollo_api/app.py`:

    - Keep `registry` as it is.
    - `_LOG = AppLogger.get_logger("apollo")` at module level.
    - `@asynccontextmanager async def lifespan(_app: FastAPI) -> AsyncIterator[None]`:
      `settings = get_settings()`, `prepare(settings)`, then
      `AppLogger.initialize(root_logger_name="apollo", level=logging.INFO, file=str(settings.logs_path / "apollo"), update_loggers={...}, force_reconfigure=True)`,
      then
      `_LOG.info("apollo started | state_dir={}", settings.state_dir.resolve())`,
      then `yield`.
    - `def create_app() -> FastApiApp`: returns
      `FastApiApp(AppConfig(registry=registry, log=log_server_errors(AppLogger.get_logger("apollo.http"))), routers=(router,), title="apollo", lifespan=lifespan)`.
    - `app = create_app()`.
    - Update the module docstring to mention the lifespan.

1. `.gitignore`: above `# BEGIN rn-forge kiln`, add

    ```text
    # apollo's runtime state and local settings
    .apollo/
    .env
    ```

## Tests first

Create `apps/api/tests/test_s1_2_2_logging.py`. Import `create_app` from
`apollo_api.app` and `get_settings` from `apollo_api.platform.settings` at the
top. A fixture sets `APOLLO_STATE_DIR` to `tmp_path / "state"` and
`APOLLO_LIBRARY_ROOT` to `tmp_path / "library"` with `monkeypatch.setenv`, and
calls `get_settings.cache_clear()` before and after the test. A helper returns
the text of every file matching `tmp_path / "state" / "logs" / "apollo*"`,
joined.

- `test_s1_2_2_1_log_file_written`: `with TestClient(create_app()): pass`. Then
  at least one `logs/apollo*` file exists and the joined text contains
  `apollo started`. `config/config.yaml` exists too (the lifespan prepared the
  tree).
- `test_s1_2_2_2_server_error_logged`: `application = create_app()`, then
  `application.add_api_route("/boom", boom)` where `async def boom()` raises
  `RuntimeError("kaboom")`. Inside
  `with TestClient(application, raise_server_exceptions=False) as client:`,
  `client.get("/boom")` has status `500`. After the block, the joined log text
  contains `problem.server_error` and `RuntimeError: kaboom`.

## Rules

- Use `task` for the toolchain. Never call `uv`, `pytest`, `ruff`, `pyright`,
  `uvicorn` or `kiln` directly. Do not start the API.
- `apollo_api` may not import `typer`, `click`, `jinja2` or `django`
  (`.importlinter`).
- pyright runs in strict mode; public modules, classes and functions in `src/`
  get docstrings. `AppLogger` uses brace-style (`{}`) message formatting.
- Tests are named `test_s1_2_2_<n>_<slug>` and live in `apps/api/tests/`.
- Add no dependency. Do not commit or push.
