# ADR-0021 — apollo.db is async on rn-forge-sqlalchemy, from one fresh baseline migration

**Status:** proposed (2026-11-15) · **Scope:** `apollo.db`: its engine,
sessions, models and migrations

## Decision

- **One async engine.** `apollo.db` is opened with
  `rn_forge.sqlalchemy.create_sqlite_engine`, which uses WAL, `busy_timeout`
  5000 ms, foreign keys on and `synchronous=NORMAL`. Request handlers, the job
  worker and the event stream share it through one `async_sessionmaker`, which
  `platform` provides with `expire_on_commit=False`. There is no sync engine.
- **Kit models.** Models derive from the kit's `Base`, with its naming
  convention. `UTCDateTime`, `AuditMixin` and `VersionMixin` are used where
  they fit. Enums stay `VARCHAR`, so a new job type needs no migration.
- **Embedded migrations.** Alembic scripts ship inside the package as
  `apollo_api:migrations`. They run at startup through
  `rn_forge.sqlalchemy.migrate.run_migrations`, in a thread, and only forward.
  The history starts from one baseline that creates the current schema. The
  old six migrations, and the `saved_search` table, are not carried
  ([ADR-0015](ADR-0015.md)).
- **beets' `library.db` is not touched by SQLAlchemy.** It belongs to beets,
  behind the actor ([ADR-0005](ADR-0005.md)).

## Consequences

- Every database call site is `async`. A job handler's blocking work goes
  through the actor or `asyncio.to_thread`, while its database writes stay on
  the loop.
- The worker uses the same engine pykit F17.6 sketches, so the queue can move to
  pykit later ([ADR-0007](ADR-0007.md)).
- No old `apollo.db` is migrated, since none was ever in real use.

## Influences

- [E1](../specs/epics/E1-backend-foundation/index.md) (F1.4, F1.6).

## Alternatives considered

- **Keep the old sync engine and `sessionmaker`.** pykit is async only, so
  apollo would keep its own engine code, and its worker would not fit F17.6.
- **Two engines, async for requests and sync for the worker.** That gives two
  session models, and two ways to get transactions wrong, over one file.
- **Port the old migration chain.** Migration 0006 rewrote singular queries to
  plural in rows that never existed outside development.

## Background

pykit F17.4, which shipped the SQLite engine and embedded migrations in
rn-forge-sqlalchemy 0.2.3, was extracted from the old apollo's `db/session.py`
and `db/migrate.py`.
