# ADR-0014 — Path agreement uses beets' own destination, and tag writes relocate in the same audited batch

**Status:** proposed (2026-11-15) · **Scope:** path comparison, "update tag from
path", and what a path-affecting tag edit does

## Decision

Apollo never reimplements beets' path sanitisation. beets evaluates the template
with `for_path=True`, then `asciify_path`, then `legalize_path` with the
replacement map, and a hand-built version is the near-miss that caused the old
bug. Apollo's projection phase, on the actor, computes `Item.destination()` and
passes it down. Both sides of any path comparison come from paths that went
through identical sanitisation, so only genuine tag/path disagreements survive.
Reported expected paths are beets' own answer verbatim.

"Update tag from path" is offered only for fields the check still reports
inconsistent, so a sanitisation artefact such as `AC_DC` for `AC/DC` is never
written back into a tag. It stays dry-run first, per-field opt-in, audited and
reversible.

Relocation is an effect of changing a path-template tag, not a routine
standalone action. A single-track dry run returns the exact old and new
destination paths plus the source mtime; apply requires that reviewed
destination and mtime, and a conflicting destination fails at preview. The tag
write, file move, index update, annotation re-key ([ADR-0010](ADR-0010.md)) and
their inverse audit entries share one batch, so undo restores path and tags
together. Bulk edits preview each relocation and perform it inside the same edit
job. Manual Relocate remains, contextual to path findings, for drift that
already happened.

## Consequences

- Path-comparison code derives both sides from `Item.destination()` or an
  equivalent beets-computed path, never from a template apollo built.
- A tag change and its file move succeed or fail together; undo reverses both.

## Influences

- [E11](../specs/epics/E11-checks-and-relocation/index.md) implements the checks
  and manual Relocate.
- [E6](../specs/epics/E6-tag-editing/index.md) applies the combined write and
  move.
- [E14](../specs/epics/E14-audit-and-maintenance/index.md) holds the audit
  batches.

## Alternatives considered

- **Compare the raw tag against the folder name.** With `asciify_paths` and a
  `replace` map, beets writes `AC_DC` for `AC/DC` and `Cafe Del Mar` for
  `Café Del Mar`, so every value with a slash, colon, control character,
  leading dot, trailing space or non-ASCII character was flagged.
- **A manual mute list for noisy findings.** Most of what it would hide was this
  bug, not a real exception.
- **Relocation as a separate manual step.** A forgotten step leaves a file and
  its tags disagreeing; catching it afterwards is worse than not creating it.

## Background

Merges old apollo ADR-0011 (recorded 2026-08-31; originally I37 in the retired
DECISIONS.md) and old ADR-0019 (recorded 2026-08-31; originally I53). The merge
on 2026-11-15 is the only change: both rest on the same rule that beets, not
apollo, decides where a file lives. The old `_expected_path` helper hand-built
`root / genre / albumartist / album / title` with no `%first{}`, replace map or
asciify step, and the old `services/checks.py::item_paths` was the actor-side
projection.
