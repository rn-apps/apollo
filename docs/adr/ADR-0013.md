# ADR-0013 — The track projection is pure and file facts are scan-time attributes

**Status:** proposed (2026-11-15) · **Scope:** how the track DTO is built and
where its file facts come from

## Decision

Building a track DTO performs no filesystem syscalls and opens no files. Every
field is a native beets `Item` field or a flexible attribute that a scan or
check job wrote while it already had the file open, off the actor, in one pass
over every file with a chunked write-back phase on the actor. File size,
missing-file state and artwork presence are stored as `apollo_filesize`,
`apollo_file_missing` and `apollo_has_art`, not computed live.

One DTO shape is therefore affordable everywhere: albums, facets, search,
playlists and the track list all return the same one, because producing it costs
only an index lookup.

The missing-file and artwork fields mean "as of the last scan or check", and the
schema says so. `hasArtwork` is `bool | None`: `None` means no scan has looked
at the file yet, which is different from `False`. The detail route upgrades it
to the file's real answer once it has read the file ([ADR-0011](ADR-0011.md)).

A test patches `Path.stat`, `exists` and `open` to raise and builds the DTO
against it, and another asserts the DTO is built in exactly one code path.

## Consequences

- Any new DTO field comes from an `Item` field or a flexible attribute a scan or
  check wrote, never from a live read at request time.
- Staleness is accepted: a file removed after the last scan shows as present
  until the next check.

- [E11](../specs/epics/E11-checks-and-relocation/index.md) writes the scan-time
  attributes.

## Alternatives considered

- **Stat each file when building the DTO.** The old code did: three syscalls per
  row, about 300 per list page and about 37,000 per album rebuild, all on the
  actor thread. Detail mode also parsed tags twice, decoding the embedded
  image each time.
- **Read `artpath` from the item.** It is an Album field, not an Item field, so
  the expression was a silent constant `False` and every list reported no
  artwork.

## Background

Restates old apollo ADR-0010 (recorded 2026-08-31; originally I38 in the retired
DECISIONS.md). Measured on the real 12,335-track index: cold album summaries
went from 2.45 s to 1.85 s (the rest is beets' own iteration and credit
inference), warm to 1 ms, and the track list to 29 ms. The old
`services/checks.py::evaluate` was the one pass that opened every file.
Unchanged in this restatement apart from wording.
