# ADR-0015 — Saved queries are transient: in the URL, or promoted to a playlist

**Status:** proposed (2026-11-15) · **Scope:** where a query may be stored

## Decision

A query is either **transient** or **promoted**. A transient query lives in the
URL (`q`, `sort`), so a hard reload or bookmark reproduces it exactly. A
promoted query is a playlist: stored, resolvable and exportable. There is no
third, weaker "saved search" storage state. "Save search" is replaced by "Copy
link", the zero-storage version of the same action.

The search route stays as a dedicated surface, a query box over the shared track
workspace ([ADR-0004](ADR-0004.md)), so the sidebar entry and existing bookmarks
keep working. The old `/searches` CRUD endpoints, which were deprecated before
removal, and the `saved_search` table are not ported. The rebuild has no
saved-search storage at all.

## Consequences

- No saved-search endpoint or table exists, and none is migrated.
- Any "save this view" feature promotes to a playlist. It must not add a fourth
  storage tier.
- The URL must carry the whole query state, or Copy link loses information.

## Influences

- [E5](../specs/epics/E5-library-browse/index.md) builds the search surface and
  Copy link.
- [E13](../specs/epics/E13-playlists-and-apple-music/index.md) owns
  smart-playlist promotion.
- [E4](../specs/epics/E4-shared-domain-components/index.md) holds the shared
  track workspace.

## Alternatives considered

- **Keep saved searches as stored rows.** A smart playlist already stores a
  query and is also listed, resolvable, exportable and pushable to Music.app.
  A saved search was a strictly weaker smart playlist, and its surface rebuilt
  a query form and a "materialise as playlist" flow that the shared track
  table already had.
- **Store nothing and remove the search route.** It breaks the sidebar entry and
  existing bookmarks for no gain.

## Background

Restates old apollo ADR-0014 (recorded 2026-08-31; originally I40 in the retired
DECISIONS.md). Change in this restatement (2026-11-15): the old design removed
saved-search storage in a release after a deprecation period, while the rebuild
never creates it, so there is nothing to deprecate or migrate.
