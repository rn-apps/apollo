# ADR-0004 — One domain component per concept; screens differ by configuration, never by copy

**Status:** proposed (2026-11-15) · **Scope:** apollo's frontend domain
components and every screen that uses them

## Decision

Each music concept has exactly one Angular component, and every screen that
shows that concept uses it. A screen varies the component through inputs: a
target adapter, a column set, a capability set or row actions. It never varies
it with a fork or a private copy.

| Concept | The one component | Replaces in the old app |
| -- | -- | -- |
| Editing one item's tags, artwork, trim, replace, clean-up and checks | the media editor side panel | `TrackDetail`, `InboxDetail` and part of `MediaInspector`, plus private modals on Errors and Inbox |
| Listing tracks or staged media | the track workspace (grid, inspector, selection toolbar) | `TrackTable`/`TrackGrid` and the own tables on Errors, Inbox, playlist detail and Albums |
| Preview, diff, confirm, apply | the dry-run flow | 11 hand-written `ConfirmDialog` sequences |
| Editing many items' tags | the bulk edit panel ([ADR-0012](ADR-0012.md)) | `BulkEditPanel` and `CommonTagsForm` |
| Job state and progress | job progress | progress markup in 5 files |
| Choosing artwork | the artwork picker | `ArtworkPanel`, with no album UI before |
| Counted facet values | the facet view | `FacetList` and `FacetTable` |

An item is addressed by a **media target**: a library track (`track:<id>`) or a
staged inbox file (`inbox:<path>`, [ADR-0018](ADR-0018.md)). The target's
adapter says which operations it supports. An operation a target lacks is shown
disabled with its reason, not hidden.

## Consequences

- The tag-edit side panel looks and behaves the same from Songs, an album,
  Errors, Inbox and a playlist.
- A new operation, such as replace, is added once and reaches every screen whose
  targets support it.
- These components are built in
  [E4](../specs/epics/E4-shared-domain-components/index.md) before the screens
  that use them. A screen story is not allowed to start its own variant.
- Primitives underneath them come from ngkit ([ADR-0003](ADR-0003.md)).

## Influences

- [E4](../specs/epics/E4-shared-domain-components/index.md) and every screen
  epic, E5–E14.

## Alternatives considered

- **Shared building blocks, composed per screen** (the old app's approach).
  `TagEditForm` was shared, yet `TrackDetail` and `InboxDetail` each composed
  it with their own dirty guard, clean-tags state machine and validation
  block. The result was three behaviours for one concept.

## Background

Combines old apollo ADR-0012 (one TrackTable) and ADR-0013 (one modal owns
dismissal), both recorded 2026-08-31, with old epic 07 N5 ("one media
workspace"), which was only partly built. Its shared `MediaWorkspace` shell was
16 lines. Owner direction 2026-11-15: "the track tag edit side panel should be
the same everywhere".
