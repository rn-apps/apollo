# ADR-0017 — Apple Music is a one-way XML import and a separate one-way export, and inbox promotion imports into Music.app

**Status:** proposed (2026-11-15) · **Scope:** every exchange between apollo and
Music.app

## Decision

Apple Music integration is two one-way channels, not a mirror.

- **Import** triggers a fresh AppleScript XML export, parses it, resolves paths
  to apollo item ids in one batched actor hop, and writes apollo playlists.
  Apple wins on conflict for playlists that exist in both places, never for
  apollo-only playlists. Every overwrite is diffed and audited with the
  previous membership, so an import is undoable from history. Smart playlists
  import as labelled snapshots of their evaluated membership, because
  `Smart Info` is a proprietary blob. Master, `Distinguished Kind` and folder
  entries are skipped by property, not by name. Matching uses
  `apple_persistent_id`; a name fallback adopts only a row no other Apple
  playlist already claims.
- **Export** pushes apollo playlists to Music.app. It is **not undoable** from
  apollo, and the UI says so. The export file is written under `.apollo/`,
  never into `~/Music`.

Inbox promotion offers a checked-by-default "Add to Music.app". It copies and
indexes the file at its library destination, optionally imports that exact file
into Music.app, and removes the inbox source only after every requested step
succeeds. Any failure leaves the inbox source in place. One audit entry stores
the Music.app persistent track id; undo removes that Music.app entry and the
index item, then moves the file back to the inbox.

## Consequences

- An apollo-only playlist is never overwritten by an import.
- Imports are reversible; export pushes are not.
- Promotion cannot lose the source file on partial failure.

## Alternatives considered

- **Two-way sync.** It makes Apple's absence authoritative over things apollo
  created, and a push cannot be undone.
- **Per-track Apple events for membership.** That means thousands of round
  trips, and `location of <track>` does not coerce to a `POSIX path` (Apple
  event error -1728).
- **Matching by name alone.** Music.app permits duplicate names; the real
  library has two playlists named "Films".
- **Guessing smart-playlist criteria.** That invents data apollo does not have.
