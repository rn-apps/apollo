# ADR-0012 — Bulk edit keeps three states end to end and compiles to the operations list

**Status:** proposed (2026-11-15) · **Scope:** bulk tag edit semantics in the UI
and API

## Decision

Bulk edit keeps three explicit states per field, from form to audit entry:
**untouched** (no change), **mixed** (the selection disagrees and the field is
left alone unless the user acts) and **delete** (explicit clear). A blank input
never emits a clear operation; clearing requires a dedicated control.

The common-tags form is a UI layer only. It compiles to the same `operations`
list that bulk edit already used, so it adds no new mutation, audit or undo
path.

## Consequences

- An accidental blank submit cannot wipe a tag across thousands of files. This
  is the failure the decision exists to prevent.
- Every bulk-editing surface, including any future one, reuses this three-state
  model. None may take a two-state shortcut.
- The state model lives in one shared tag-editing component
  ([ADR-0004](ADR-0004.md)), so a new surface imports it rather than
  rebuilding it.

## Influences

- [E6](../specs/epics/E6-tag-editing/index.md) implements the common-tags form
  and the operations list.
- [E4](../specs/epics/E4-shared-domain-components/index.md) holds the shared
  editing component.
- [E14](../specs/epics/E14-audit-and-maintenance/index.md): every bulk edit is
  one audited, undoable batch.

## Alternatives considered

- **Delete a key whenever values differ.** The archived predecessor did this,
  which made "every track has this field blank" indistinguishable from "the
  tracks disagree".
- **Two states, with blank meaning clear.** It is the same collapse in another
  form and has the same wipe risk.
- **A separate bulk mutation endpoint for the form.** It would need its own
  audit and undo handling for no gain over the operations list.

## Background

Restates old apollo ADR-0004 (recorded 2026-08-31; originally I12 in the retired
DECISIONS.md). The predecessor's own earlier version had the three states right,
and a later regression collapsed them to two. The restatement drops nothing; the
form now belongs to a shared Angular component rather than a SvelteKit page.
