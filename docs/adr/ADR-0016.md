# ADR-0016 — Beets' plural tag vocabulary is the public vocabulary

**Status:** proposed (2026-11-15) · **Scope:** field names in the API, the UI
and URLs

## Decision

Apollo exposes beets' plural storage field names directly in the API, the UI and
URLs: `genres`, `composers`, `lyricists`, `arrangers`, `remixers`. There is no
translation layer between a singular user vocabulary and beets. Singular query
tokens are not accepted, and singular URLs are not redirected.

The identity editor is backed directly by beets' `artist` field. The UI splits
it into main and featured pills for editing and rejoins them into the one field
on save; main and featured are not stored as separate fields.

`albumartist`, artist pills, composers and lyricists share one role-agnostic
`contributors` autocomplete facet. It aggregates names from all four roles and
counts each name once per track. The underlying tag fields and their
role-specific facets stay distinct for storage, filtering and browsing, so the
facet is a UI convenience, not a merge of data.

## Consequences

- There is no compatibility shim to maintain or to drift from beets' field
  names.
- A beets change to the plural names forces a decision here, not a silent patch.
  If beets removes or renames one, either a shim or a migration of stored
  queries and URLs is needed, and that is recorded as a new ADR.

## Influences

- [E6](../specs/epics/E6-tag-editing/index.md) edits multi-value fields and the
  identity pills.
- [E5](../specs/epics/E5-library-browse/index.md) filters and facets on the
  plural names.
- [E13](../specs/epics/E13-playlists-and-apple-music/index.md) stores queries
  using the plural tokens.

## Alternatives considered

- **Singular public vocabulary behind a compatibility shim.** It matched the
  user's mental model and Apple Music's labels, but the old
  `library/compat.py` was a permanent surface crossed by every read, write and
  sort, and it collapsed multi-valued tags to their first value for display.
- **Separate main and featured artist fields.** They would split one beets field
  into two stores that must be kept in agreement.

## Background

Restates old apollo ADR-0015 (recorded 2026-08-31; originally I50 and I51 in the
retired DECISIONS.md). beets 2.13 removed its singular multi-value fields
(`genre`, `composer`) in favour of plurals. The old design first tried a
singular vocabulary with a shim, then retired it. The rebuild starts from the
plural vocabulary, so there is no shim to delete and no stored singular tokens
to migrate.
