# ADR-0019 — Code is layered one way, back end and front end, and the layering is enforced by lint

**Status:** proposed (2026-11-15) · **Scope:** imports inside `apps/api` and
`apps/web`

## Decision

**Backend** (`apollo_api`). Each layer imports only from layers below it:

1. `platform`: settings, runtime paths, errors, the database engine and
   sessions, the job runtime and the event stream. apollo's glue over pykit,
   with no music knowledge.
1. `media`: file and tag I/O, artwork, audio probing and the external tools.
1. `index`: the beets actor, projections, snapshots and paging.
1. `proposals`, `validation` and `apple`: read-only analysis, and Music.app.
1. `workflows`: the use cases. Every dry run, audit and apply lives here.
1. `jobs`: handlers, each a thin adapter from a job context to a workflow.
1. `routes`: HTTP only. Validate, call one workflow or submit one job, translate
   the result.

`app.py` is the only composition root. Every long-lived resource is created in
the lifespan and drained in reverse.

**Frontend** (`apps/web/src/app`). `core` (API client, generated types, the
status store and stream) → `shell` (rail, palette, bottom bar, breadcrumbs) →
`domain` (the shared components of [ADR-0004](ADR-0004.md)) →
`features/<screen>`. A feature never imports another feature.

## Consequences

- The backend contracts are added to `.importlinter`, below kiln's block. The
  frontend contracts go in `apps/web/eslint.config.mjs` (repo-owned).
  `task lint` fails on a wrong-way import.
- A route holds no domain logic. ruff's complexity limit (10) stays the
  backstop. The old inbox router (684 lines) is the case this prevents.
- Generic `platform` code is the candidate for pykit extraction, and is kept
  free of apollo types so that a move is mechanical.

## Alternatives considered

- **Package by feature (a `tracks/` and an `inbox/`, each with its own routes,
  workflows and media code).** Inbox and library tracks share most operations
  through media targets. Feature packages would either duplicate them or
  import each other sideways.
- **Layering by convention only (the old app).** Its rule was documented but not
  checked, and its routers grew domain logic anyway.
