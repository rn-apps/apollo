# ADR-0010 — Annotations hold only facts no audio frame can carry

**Status:** proposed (2026-11-15) · **Scope:** what `apollo.db` may store about
artists and albums, and how it is keyed

## Decision

A field belongs in the artist or album annotation table of `apollo.db` if and
only if no audio frame can carry it (artist type, birth date, gender, avatar).
Anything derivable from tags stays in beets alone and is never mirrored.

Annotation keys are normalised natural keys, not beets row ids, so a full
library rebuild reproduces them and reattaches automatically:

- An artist annotation is keyed on the artist name, NFC-normalised, casefolded,
  whitespace-collapsed and stripped. The raw value is kept separately for
  display. The key changes when the artist tag is edited.
- An album annotation is keyed on the album directory, not on the
  `(albumartist, album)` tag values. Its key changes only when a relocation
  moves the directory, in the same audited operation.

No identity tag is written into audio files to survive renames made outside
apollo. A rename made while apollo is not running surfaces as an orphan on a
manual relink page, with ranked candidates to relink, merge or delete. Nothing
is applied automatically; every relink is audited and undoable.

## Consequences

- Artist type `BAND` suppresses comma-splitting during credit inference, so
  annotations are a functional input, not only display metadata.
- Two exposures are accepted. An external retag made while apollo is not running
  orphans the annotation (reported, not lost). The album key omits year, so
  same-artist albums with an identical title collide.
- A test that no annotation field duplicates something a frame carries is
  required. The old `mb_artistid` on the artist annotation is a known
  candidate violation; do not port it without that test.

## Alternatives considered

- **Relational Artist/Album/Genre/Song tables mirroring tags.** The archived
  predecessor did this and grew a validate/correct/compare subsystem whose
  only job was fighting the drift it created. A third authoritative store also
  breaks the audit invariant: undo would have to revert files, beets and the
  ORM atomically.
- **An `apollo_album_uid` identity tag in every file.** It mutates the whole
  library to defend against a rare external rename.
- **Keying albums on `(albumartist, album)`.** Tags edited outside apollo would
  orphan the annotation, and re-keying would fire on every tag edit. A
  `year`-in-path restructure to fix title collisions was rejected: no
  collision was observed, and it would fragment albums with inconsistent
  per-track years.

## Background

Restates old apollo ADR-0002 (recorded 2026-08-31; originally I10, I15, I16 and
I17 in the retired DECISIONS.md). Measured against the real library: 1,777
distinct `(albumartist, album)` pairs map 1:1 to 1,777 album directories once
`Disc N` is collapsed, and every multi-directory pair is a genuine multi-disc
album. Unchanged in this restatement apart from wording; the old SvelteKit
relink route is described by role only.
