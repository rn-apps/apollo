# ADR-0011 — Artwork is served by endpoint and never inlined in lists

**Status:** proposed (2026-11-15) · **Scope:** how cover art reaches the UI

## Decision

Cover art is served by `GET /v1/tracks/{id}/artwork`, with a real content type,
a strong `ETag` and thumbnails. It is never inlined in list or grid payloads.
The track DTO exposes only `has_artwork`, computed once at scan or check time
off the actor ([ADR-0013](ADR-0013.md)), so the UI knows whether to request the
endpoint at all.

Base64 survives as one narrow, explicit opt-in:
`GET /v1/tracks/{id}?artwork=true` on a single track, for the one case that
legitimately needs inline bytes, comparing artwork across a bulk selection. It
forfeits the `ETag` and the long-lived browser cache, so it is never the default
transport.

## Consequences

- Grid and list rendering never touches the beets actor for image bytes; only an
  explicit artwork request does.
- The `ETag` lets the browser cache art across navigations while the file is
  unchanged.
- A future bulk-comparison view reuses the single-track opt-in. Do not
  generalise it to a bulk endpoint without re-deciding this.

## Influences

- [E7](../specs/epics/E7-artwork-and-annotations/index.md) serves and edits
  artwork.
- [E5](../specs/epics/E5-library-browse/index.md) renders grids that only
  reference the endpoint.
- [E4](../specs/epics/E4-shared-domain-components/index.md) holds the one
  artwork component.

## Alternatives considered

- **A base64 `artwork` field on list payloads.** Cover art runs 100 KB to 2 MB
  per file. Base64 inflates that by about 33%, cannot be `ETag`-validated or
  cached inside a JSON body, and would make the single beets actor thread read
  and decode image bytes for every visible row.
- **A bulk base64 endpoint for comparison.** It keeps the same cache loss and
  actor load, and the single-track opt-in already covers the use.

## Background

Restates old apollo ADR-0003 (recorded 2026-08-31; originally I11 in the retired
DECISIONS.md, confirmed by I38), with a confirming measurement in the old log.
The archived predecessor app reached the same conclusion independently: its tag
payload returned only `len(artwork)` and served bytes from a dedicated endpoint.
The route now sits under the `/v1` prefix; the decision is otherwise unchanged.
