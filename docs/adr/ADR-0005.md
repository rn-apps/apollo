# ADR-0005 — One actor thread owns beets; blocking work runs off the event loop and off the actor

**Status:** proposed (2026-11-15) · **Scope:** every access to beets' `Library`,
and where blocking work runs

## Decision

- **One actor.** Only the library actor, a commons `ThreadActor[Library]`, may
  touch a beets `Library` or `Item`. Async code calls `await actor.run(fn)`.
  Job handlers call `actor.submit(fn)` and wait on the returned `Future`.
- **Hold the actor only for beets work.** An operation that needs files, a
  subprocess (`ffprobe`, `ffmpeg`, `osascript`) or the network works in three
  phases:
    1. On the actor, do the beets reads or writes.
    1. On the actor, project the result into plain data, such as
       `[(id, path, mtime)]`.
    1. Off the actor, do the file or network work as a fan-out through
       `TaskPool.map_settled`, and pass the results back to the actor if they
       must be written.
- **Never block the event loop.** File, tag, image and subprocess work in a
  request path goes through `asyncio.to_thread`. It never runs inline in an
  `async def`.

## Consequences

- beets' SQLite index and `Library`, which are not safe for concurrent use,
  cannot be corrupted by concurrent access, by construction.
- Every operation pays a queue hop to the actor. A slow actor call delays every
  other read, which is why full-library reads are cached
  ([ADR-0006](ADR-0006.md)) and paging is pushed into SQL.
- No beets object crosses into a `TaskPool` task or into a response model. Tests
  pin this for the actor's public calls.

## Influences

- [E1](../specs/epics/E1-backend-foundation/index.md) (F1.5), and every backend
  feature in E5–E14.

## Alternatives considered

- **A lock around a shared `Library`.** It serialises the same way, but nothing
  stops a caller from holding a beets object past the lock, which is the
  failure the actor rules out.
- **Keep the old `LibraryActor`.** commons 0.9.0 ships `ThreadActor` (pykit
  F17.2), which was extracted from it. apollo keeps only the beets setup.

## Background

Restates old apollo ADR-0008 and `docs/architecture/actor.md` (recorded
2026-08-31). The old app measured `list(lib.items())` at 793 ms on a 12k-track
library when it ran in a request path, and its `fetch_page` `LIMIT/OFFSET` path
brought a page down to 18 ms, against about 900 ms through beets.
