# ADR-0007 — Durable jobs run in-process from apollo.db, with no broker; leftover work waits for the user

**Status:** proposed (2026-11-15) · **Scope:** every long-running operation

## Decision

- **No broker.** Jobs are rows in `apollo.db`, and an in-process worker claims
  and runs them, so a scan, bulk edit, relocate, download, replace, trim,
  check, artwork, intake or Apple job survives a restart. Progress and logs
  are persisted as each job runs. Cancellation is cooperative, through a
  checkpoint the handler calls.
- **apollo owns the worker for now.** pykit's durable job queue (F17.6) is
  deferred until a second application needs it. apollo writes its worker on
  the async engine ([ADR-0021](ADR-0021.md)) and in the shape F17.6 sketches:
  `Job`/`JobLog` models, an async claim loop, and a handler that receives a
  job context. If the queue moves to pykit later, the change is a re-point,
  not a redesign.
- **Leftover work waits for the user.** At startup, jobs that were `pending`
  from a previous run are held, and jobs that were `running` are marked failed
  ("interrupted by restart"). Held jobs run only after an explicit Resume in
  the UI. A job submitted after startup runs at once.
- **Fan-out inside a handler** uses `TaskPool.map_settled`. It is never the job
  runtime.

## Consequences

- No job silently re-runs on a reload, and the old `APOLLO_JOBS_AUTOSTART` flag
  is gone, along with the deploy step it required.
- The worker carries what a broker would otherwise carry: bounded claiming by
  capacity, wake-on-submit, bounded shutdown grace, restart recovery, and
  pruning history to a limit (500).
- Each job type declares whether it mutates the library
  ([ADR-0006](ADR-0006.md)).

## Influences

- [E1](../specs/epics/E1-backend-foundation/index.md) (F1.6) and every
  job-backed feature.

## Alternatives considered

- **Celery, Dramatiq, RQ or arq.** Each needs a broker process the user must
  supervise, which contradicts [ADR-0001](ADR-0001.md).
- **Wait for pykit F17.6.** It has no entry date. Blocking on it would block
  every job-backed epic.
- **Hold all work until Resume, gated by a flag (the old default).** It solved
  the reload replay, but it also held new work, and it needed a flag flipped
  before any real use.

## Background

Restates old apollo ADR-0005 (I26) and ADR-0007 (I28), recorded 2026-08-31.
*Changed 2026-11-15:* the old flag held everything by default. Now only work
left from a previous run is held, which keeps the reload safety the flag was
