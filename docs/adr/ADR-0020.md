# ADR-0020 — The API is the rn-forge web standard at `/v1`, with one documented paging exception, and the client is generated

**Status:** proposed (2026-11-15) · **Scope:** the HTTP contract between
`apps/api` and `apps/web`

## Decision

- **Standard composition.** The API is `rn_forge.fastapi.FastApiApp` at `/v1`,
  with the kit's health endpoints (`/livez`, `/readyz`) and security headers.
  apollo's own status, with tool versions and capabilities, is
  `GET /v1/status`.
- **Errors are RFC 9457 problems.** `ApolloError` subclasses carry a stable
  hyphenated `code` and a `status_code`, and are registered with
  `register_hierarchy`. A problem's `type` is `/problems/<code>`, and its
  structured detail travels as problem extensions. The client matches on the
  `type`, through ngkit's problem helpers.
- **Tracing, not a request id.** The kit's `traceId` replaces the old
  `X-Request-ID` middleware.
- **Paging.** Lists stored in `apollo.db` (jobs, audit, playlists) use the kit's
  cursor pagination. Lists backed by beets (tracks, albums, inbox) use offset
  paging that returns `total`, because the virtual grid needs the full height
  to scroll and seek. Those lists cannot use the kit's `keyset`, which serves
  SQLAlchemy selects only.
- **Generated client.** The TypeScript types are generated from `/openapi.json`
  by a repo task, are committed, and are never hand-edited. A test fails if
  the generated types are stale.
- **Body limit.** It is raised from the kit's 1 MiB to 25 MiB for artwork
  uploads. Everything is served same-origin through the dev proxy, so CORS is
  not enabled.

## Consequences

- The old `{"error": {...}}` envelope, the `/api/v1` prefix and `/health` are
  gone. Nothing depends on them.
- The offset exception is apollo's only departure from the kit's API rules, and
  this ADR is where it is recorded.
- `rn-forge-fastapi` has no codegen extra (pykit E11 is deferred), so the
  generator is a dev dependency in apollo.

## Alternatives considered

- **Keep the old envelope.** It would mean a custom handler, which is what
  `FastApiApp` exists to remove, and ngkit's client recognises only problems.
- **Cursor paging everywhere.** The grid would lose its scrollbar position and
  random seeking across 12k rows, and the old 60 fps gate assumes a known row
  count.
- **Hand-written client types (the old pages).** They drifted from the API, even
  though the old app already generated a schema it did not use.
