# ADR-0003 — Generic UI primitives are built and released in ngkit before apollo uses them

**Status:** proposed (2026-11-15) · **Scope:** where apollo's frontend
components live

## Decision

A component that knows nothing about music is a **primitive**. Examples are a
button, modal or drawer, confirm dialog, toolbar, chips input, autocomplete,
field control, state block, badge, tabs, toast, progress bar and data grid.
Every primitive is built in ngkit's `@rn-forge/ng-tailwind` and released there.
apollo then consumes it at a pinned release. apollo's own `apps/web` holds only
**domain components**, which know apollo's types and API, and the shell.

- Behaviour (focus, keyboard and ARIA) comes from `@angular/cdk` and
  `@angular/aria` inside the primitive, as ngkit E9 requires.
- apollo themes the primitives through ngkit's `--rnf-*` tokens, in one theme
  file of its own. Its components never restyle a primitive's internals.
- Client plumbing comes from `@rn-forge/ng` too: problem helpers, the event
  stream and resource invalidation.

## Consequences

- apollo's screens are gated on ngkit releases. The primitives each foundation
  story needs are listed in [E3](../specs/epics/E3-ngkit-primitives/index.md)
  and must ship in ngkit first. ngkit E9, which is deferred today, has to be
  scheduled, and the primitives it does not plan need new ngkit work.
- An apollo story that finds a missing primitive stops and adds it to E3. It
  does not build a local stand-in.
- ngkit ships as GitHub Release tarballs at one version for all its libraries,
  so each primitive apollo adopts means an ngkit release and a pin bump.

## Alternatives considered

- **Build primitives in apollo's `ui/`, extract later** (the 2026-10-20 plan).
  It is faster to start, but extraction becomes a second project, and in the
  meantime apollo carries a local kit that drifts from ngkit's rules.
- **Use `@rn-forge/ng-bootstrap`.** apollo's design is a dense dark workstation
  with its own palette. Tailwind v4 over neutral tokens fits it, and
  Bootstrap's component look would have to be fought.
- **A third-party kit (Angular Material, PrimeNG).** It would bring a second
  design language and theming system next to ngkit's, for one consumer.

## Background

Owner decision, 2026-11-15. At that date `@rn-forge/ng-tailwind` 0.4.0 exports
only `RnfButton` and its token, base and Tailwind stylesheets. E9 lists 11 more
primitives and is deferred with no release.
