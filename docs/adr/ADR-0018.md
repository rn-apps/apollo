# ADR-0018 — Inbox media is identified by path, not a fabricated id

**Status:** proposed (2026-11-15) · **Scope:** how staged inbox files are
referenced before promotion

## Decision

Staged inbox media is identified by its relative inbox path and represented in
shared UI and queue components as `{kind: "inbox", path}`. It never receives a
fabricated beets item id before promotion. Parse and promotion are dedicated,
URL-addressed review views built around this path identity.

Playback queue entries carry explicit audio and art URLs and a target key of
`track:<id>` (a catalogue item) or `inbox:<path>` (a staged item), so both share
one playback transport without either pretending to be the other's identity
scheme.

The inbox uses the shared track workspace ([ADR-0004](ADR-0004.md)) with an
inbox column set. Path-backed bulk edits on inbox items apply synchronously
under one audit batch rather than creating a job, since inbox review is small
and interactive.

## Consequences

- No code path assigns a synthetic or placeholder beets id to an inbox file. Any
  component that references staged media handles the `{kind: "inbox", path}`
  shape explicitly.
- Inbox trim reuses the replacement pipeline but does not stamp
  `apollo_trimmed_at` or apply the library-root iCloud guard, since staged
  files live under apollo state, outside the guarded media library.

## Influences

- [E8](../specs/epics/E8-inbox-and-intake/index.md) builds the inbox views and
  promotion.
- [E4](../specs/epics/E4-shared-domain-components/index.md) holds the shared
  workspace and queue components.
- [E10](../specs/epics/E10-trim-and-replace/index.md) supplies the trim pipeline
  that inbox trim reuses.

## Alternatives considered

- **Assign a temporary beets id on staging.** It invents an identity beets does
  not have, and it would leak into audit entries and queue keys.
- **A separate queue and component set for inbox files.** It duplicates the
  playback transport the shared components already provide.

## Background

Restates old apollo ADR-0018 (recorded 2026-08-31; originally I52 in the retired
DECISIONS.md). Change in this restatement (2026-11-15): the old decision gave
the inbox table a fixed seven-column layout with no column manager. That clause
is dropped. The inbox now uses the shared track workspace of ADR-0004 with an
inbox column set, so it shares one table with the catalogue and its per-viewer
column preferences.
