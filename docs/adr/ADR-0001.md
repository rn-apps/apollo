# ADR-0001 — apollo is a local-first, single-user music workstation over files apollo does not own

**Status:** proposed (2026-11-15) · **Scope:** what apollo is, and the rules
every feature must keep

## Decision

apollo manages one person's music library on one Mac. It is a FastAPI backend
and an Angular single-page app, served on `127.0.0.1` with no accounts.

- **Audio files are the source of truth.** Tags live in the files. beets is the
  tag and index layer over them, and its `library.db` can be rebuilt by a
  scan.
- **apollo's own state is reconstructible, or it is an explicit repeatable
  cache.** `apollo.db` holds only what no file can carry: jobs, the audit log,
  playlists, annotations ([ADR-0010](ADR-0010.md)), check results and
  Music.app statistics. The last two are caches keyed so that a rescan refills
  them.
- **Every mutation is dry-run first, audited and reversible**
  ([ADR-0009](ADR-0009.md)).
- **The real library is not touched until the acceptance gates pass**
  ([E15](../specs/epics/E15-acceptance-and-cutover/index.md)). Until then
  apollo runs against a copied fixture library.

No network metadata service (MusicBrainz, AcoustID, an LLM) is in scope. The
only network uses are yt-dlp downloads and artwork fetched from a URL.

## Consequences

- No auth, multi-user, sync or remote-access features. `rn-forge-fastapi`'s auth
  surface is left unused.
- A feature that needs to store something no file can carry must say which
  rebuild or cache rule covers it.
- apollo is run from the repository (`task api:dev`, `task web:dev`) in v1. It
  is not installed as a tool (`lifecycle = false`). An installer is a parked
  idea.

## Influences

- Every epic. Especially [E1](../specs/epics/E1-backend-foundation/index.md),
  [E14](../specs/epics/E14-audit-and-maintenance/index.md) and
  [E15](../specs/epics/E15-acceptance-and-cutover/index.md).

## Alternatives considered

- **Music.app as the source of truth.** Its library is opaque and its tags are
  only reachable through AppleScript, and iCloud Sync Library rewrites them.
  apollo instead imports from Music.app one way and pushes to it one way
  ([ADR-0017](ADR-0017.md)).
- **apollo's own catalogue database instead of beets.** That would mean
  reimplementing beets' query language, path templates and mediafile layer,
  which the old apollo relied on across 10,559 lines of backend code.

## Background

Restates the old apollo's README and `docs/architecture/principles.md` (five
load-bearing rules, recorded 2026-08-31). The old build implemented milestones
M0–M9 but was never run against the real library: all of its acceptance gates
were still open when it was retired on 2026-11-15.
